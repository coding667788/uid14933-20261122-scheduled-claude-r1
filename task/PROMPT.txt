请给安全调查组做一项证据归属复核。团队将机密报告分发给多名虚构接收人，在不同位置嵌入了系统登记的水印符号。后续采集到的图像识别结果已经转换成合成符号阵列。工作内容仅限对登记证据做离线校验，不编写水印嵌入、图像处理或跟踪程序，不使用实际个人记录。

目录列出发行批次、接收人编号、该份拷贝的码字及允许缺失的位置。输入证据片段指明批次候选、已知原始位置的符号、擦除位置和签名见证的可信标记。每个非擦除位置可附高低两类可信度；匹配时可信高位不允许差异，低可信差异按输入整数代价累计，并受单片及整案双重上限。多个片段可以来自同一份拷贝，但同一逻辑位置的来源、符号及重复证据代价必须按统一的原始位置模型对齐；重复观察同一次错误不能重复收费，独立观察不得被合并。移交登记分配拷贝在不同保管阶段的接收人，归属必须定位到事件发生时的阶段。保管补录有版本，阶段可能合并或拆分，已发布结论保留对应目录视图。

在所有符合固定证据、片段同源/异源约束、每个批次责任人上限与代价预算的解释中，report 给出最小涉及拷贝数、最低总差异代价，最终按片段 ID 对应的一组来源 ID 决胜。audit 以证据证明责任为主，逐个接收人判定是必然、可能还是不可能相关；只有在每种可行解释都只指向同一人时才允许输出唯一归属，否则给至少两份完整兼容见证。不存在解释时报告包含极小的冲突片集合，按 ID 降序逐一试删定义结果。支持 28 个片段、每片 5 个候选、最多 80 个已观察位置。验收覆盖只按每片最近距离会误指认、移交与样本批次混淆、擦除不算匹配、两个碎片共享错误而预算可通过、低可信观察过多引起联合否决、以及新版纠正不改历史。用独立搜索核对小案。

程序只需 Windows 原生 Python 3.12、CPU 和标准库。以命令 python -m watermark_audit CASE.json 运行，UTF-8 JSON 报告能够稳定重现。交付从空目录生成的源代码、可经 unittest 执行的虚构数据测试和带 IO 定义及复跑步骤的 README，解析错误指出准确字段。
